## Environment Variables

All required vars are in `.env.example`. Critical ones:

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | PostgreSQL connection string |
| `OPENAI_API_KEY` | GPT-4o calls (never call this in tests — use mocks) |
| `CLERK_SECRET_KEY` | Auth (backend) |
| `VITE_CLERK_PUBLISHABLE_KEY` | Auth (frontend) |

**Never call the real OpenAI API in tests.** Use `vi.mock('../openai-client')`.

## Directory Map

```
src/
  api/          Express route handlers — thin, delegate to services
  services/
    crawler.ts       Fetches HTML (Cheerio-based, not Puppeteer in v1)
    scorer.ts        AeoScorer — pure function, no side effects
    signals/         One file per AEO signal (e.g. faq-schema.ts)
    suggestions.ts   Calls GPT-4o, returns Suggestion[]
    prompts/         Versioned prompt templates (testable strings)
  db/
    schema.ts        Drizzle ORM table definitions (source of truth)
    index.ts         DB connection pool
    migrations/      Auto-generated by Drizzle — do not hand-edit
  utils/
    html-parser.ts   Shared Cheerio helpers
    schema-builder.ts  JSON-LD construction helpers

client/src/
  components/     Dumb UI components (ScoreGauge, SignalRow, SuggestionCard)
  hooks/          useAudit, useHistory, useSuggestions
  pages/          Dashboard, Audit, History, Report
  lib/
    api.ts         Typed fetch wrappers (all API calls go through here)

  unit/           Mirrors src/ structure exactly

  e2e/            Playwright tests

```

## Key Conventions

### TypeScript
- Strict mode is ON — no `any`, no `@ts-ignore`
- Path alias `@/` maps to `src/` (api) and `client/src/` (client) respectively
- All async functions must handle errors — no unhandled promise rejections

### Testing
- **Write the failing test FIRST.** Do not write implementation without a red test.
- Use `tests/fixtures/` HTML files for deterministic scoring tests (never fetch live URLs in tests)
- OpenAI must be mocked via `vi.mock` — never real API calls in CI
- Each signal in `src/services/signals/` must have a matching test file in `tests/unit/signals/`

### Database
- Schema lives in `src/db/schema.ts` — Drizzle is the source of truth
- Run `npm run db:generate` after schema changes, then `npm run db:migrate`
- Never write raw SQL in route handlers — always use Drizzle query builder
- Do not store raw HTML longer than 24h (GDPR consideration)

### AEO Signals
- Each signal is a pure function: `(html: CheerioAPI) => SignalResult`
- Signals live in `src/services/signals/<signal-name>.ts`
- The rubric weights are defined in `src/services/scorer.ts` as a const — only change weights after updating `docs/spec.md` first

### GPT-4o Prompts
- Prompts live in `src/services/prompts/` as exported string templates
- Never inline prompts in service logic — keep them isolated for testability and versioning
- Use the `gpt-4o` model, not `gpt-4-turbo` or `gpt-3.5-turbo`
- Always set `max_tokens` to avoid runaway costs

## Workflow for a New Signal

1. Add the signal key to `SignalKey` type in `src/types.ts`
2. Write the test in `tests/unit/signals/<signal-name>.test.ts` (red)
3. Implement `src/services/signals/<signal-name>.ts` (green)
4. Register it in `src/services/scorer.ts` with its weight
5. Add the weight to the table in `docs/spec.md §2.2`
6. Update `CLAUDE.md` Lessons Learned if you found a gotcha

## Gotchas

- Cheerio's `$('script[type="application/ld+json"]')` can return multiple tags — iterate all of them
- Some sites put JSON-LD in `<body>` not `<head>` — scan the full document
- `<meta description>` is `$('meta[name="description"]').attr('content')`, not `.text()`
- OpenAI streaming responses require `stream: true` and an SSE-compatible response handler
- Drizzle's `migrate()` must run before the server starts (see `src/index.ts`)
- Clerk middleware must come BEFORE route registration in Express
